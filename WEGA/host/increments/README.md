# Increments: the plan of the project

The plan, and nothing else, as increments done one after the other. What is known goes to `host/KNOWLEDGE.md`, the old
compilers to `host/OLDCC.md` (running notes: `host/OLDCC_LOG.md`), the state of a program to `compare/NAME/findings.json`.

## How to read (for an AI)

1. `../../CLAUDE.md` (rules, building, checkall).
2. This file: the order and which increment is active.
3. Only the file of the active increment. It names what else to read (files and sections); read nothing else up front.

An increment file has always the same sections: Status, Goal, Done when, Read first, Known, Steps, Decisions, Not part of it,
Log. Keep it current while working: tick off steps, add to Log (dated, one line, with the commit), record the owner's decisions
with their date. A decision the owner has to make goes to "Decisions" as an open question before it is acted on.
When "Done when" holds: Status done, the next increment active, this table updated.
