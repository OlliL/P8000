## Known

- PLZ/ASM sources of libc and the kernel are assembled by the original `as` today.
- /lib/as2, /lib/asz2, /lib/as2d, /lib/asz2d (measured 2026-11-19 in increment 150, set aside to here by the owner):
  - Pass 2 of `/bin/as` (strings of as: "plzasm 1.6 800206", "plzio 810325", "Overlay file: %s", the four paths
    /lib/as2, /lib/asz2, /lib/as2d, /lib/asz2d). as2 (33280 bytes code) and asz2 (30208) are overlays E705, code only,
    stripped, bss 1030 (as /bin/as); as2d (26368) and asz2d (26880) are E705 with data only (code 0, bss 0). Entry 0x36.
  - as2 and asz2 are byte-equal up to 0x2c08; as2d and asz2d have 26028 equal bytes in their common length.
  - Layout of as2 (asz2 the same up to 0xf6a): 0x0000 the C start-up code of the system (crt0, no pad; `_environ` at
    0x6d00), 0x0036 the entry (calls 0x0ea2, 0x0ebe, 0x0f3c, then 0x0f6a, exit by 0x0a78), up to 0x0a78 code of the
    C compiler (codgen patterns, the prologue at the end of the function reached by `jr`, unoptimized moves such as
    `ld r7,r7`: probably cc without -O; plzio?), 0x0a78..0x0f6a C library members (whichlibc: cuexit, cnvt, decimal,
    length, malloc, close, creat, ioctl, lseek, open, read, brk, write, cerror; best libc-v2 with gaps 0x0e4a..0x0e94,
    0x0eb0..0x0ec4), from 0x0f6a to the end (about 28 KB) code with frame pointer r14 (`push @r15,r14; ld r14,r15;
    sub r15,#n; ldm %FFF4(r14),r8,#6`, bytes widened by `xorb rh7,rh7`): never produced by cc; the PLZ/SYS compiler.
  - The same family: `/bin/as` (E711, code 46592, data 27904, bss 1030), `/usr/lib/plzcg2`, `/usr/lib/plzcg3` (E705
    overlays, bss 1030, entry 0x104a) with `plzcg2d`, `plzcg3d` (data only). Counts of `push @r15,r14`: as2 187,
    asz2 173, as 252, plzcg2 421, plzcg3 222.
  - Data: /bin/as has 27904 = 0x6d00 bytes of data, the overlays use its bss (`_environ` at 0x6d00); as2d covers
    0x0000..0x6700 of that data space (as presumably reads it in before the exec of the overlay; not traced yet), so
    0x6700..0x6d00 of the data of as stays for pass 2.
  - Build: `ld -O` writes the magic E705 (`oflag`, src/cmd/ld/ld.c); how the code-only and data-only files were split
    (a tool, or ld options -b/-t for the section addresses) is not known yet.
  - Needs the PLZ/SYS compiler (plzsys, plzcg) for the 28 KB; the C part and the libc part could be done before.
