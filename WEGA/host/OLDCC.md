# The old C compilers of WEGA

What is known now about the C compiler revisions that built the WEGA binaries: the versions we rebuild, how they differ
from the shipped compiler, and which object shows which difference. This file holds current facts only. How they were
found, attempts, refuted ideas and removed switches are in `OLDCC_LOG.md`; which function needs which switch is in
`OLDCC_SWITCHES.md` (generated); the evidence per function is in the findings.json of each program
(`compare/*/findings.json`). The rules for this work are in `HOWTO_reconstruct.md`, "Evidence rules".

## State

With `make PROG CC=ccv0p` and strip these are byte-identical with the originals: cpp, cparse, scparse, codgen, scodgen,
popt, spopt. With v1: size, strip, mv (also cp, ln), rm. With v1r: write, rmdir. With v0: dc, ranlib. With vc (sccvc): /bin/cas, /lib/gopt. With vm: the programs of 11/18/83 (make, diff, mail, ar, cpio, nl and others). v1q builds libc modules of its time. v1 and v0 are not complete (section 5).

## 1 Terms and building

- **shipped**: the compiler of the WEGA 3.1 tree (`/bin/cc`, `/bin/scc` and their passes `/lib/cparse`, `/lib/codgen`,
  `/lib/popt`, `/lib/scparse`, `/lib/scodgen`, `/lib/spopt`). Our normal build uses it.
- **old**: a revision of the compiler that built an original binary and of which no binary exists. Its output is only
  known from the binaries it made.
- **Dn**: one difference between the output of an old compiler and that of the shipped one (section 3).
- **switch** `OLD_Dn`: a compile-time switch in the sources of a pass that turns the shipped behaviour into the old one.
  The normal build sets none, so it stays byte-identical with the shipped passes.
- **version** vN: a set of switches that together give one old compiler (section 2), built in `src/cmd/<pass>/vN` and
  run through the driver `ccvN`.
- **witness**: a function whose original code a switch makes equal. **Test bench**: `host/recon/witness.py`, the
  System III sources of WEGA programs of one compiler time, compiled with a version and aligned with the originals. WEGA
  changed many of these sources, so a difference on the bench is not a compiler difference by itself.

`cc` runs cpp > cparse > [gopt] > codgen > popt > cas > ld (`scc`: scparse, scodgen, spopt, sld). cparse writes the
intermediate tree (`.I`) and the data as cas text (`.D`); codgen chooses registers, frame and instructions; popt is the
peephole optimizer (descends from the Plexus `c2`); cas decides the jump forms.

- The old versions are native WEGA programs only (built with the shipped cc, run in the emulator). The host versions
  (`host/cc/codgen`, `host/cc/popt`, ...) get no switches, except `host/cas/casold`, used by the models.
- One source and one Makefile per pass; every old version is a target of it, built in its own directory with its switches
  (`src/cmd/cc/cparse/build/nonsegv1`, `codgen/build/nonsegv1q`, ..., the segmented v1 passes in `build/segv1`; `make old`,
  `make oldinstall`). The cas of v0 and v0p is `make oldcas` in `src/cmd/cas` (built in `old/`). Built programs are not in git.
- The driver `cc.c` with `OLD_V1`, `OLD_V0`, `OLD_V0P` runs `/lib/vN/cparse`, `codgen`, `popt`. `sccv1` (`-DSCC -DOLD_V1`) runs `/lib/v1/scparse`,
  `scodgen`, `spopt`, built with the switches of v1. v0 and v0p run `/lib/old/cas`;
  v1 runs `/bin/cas`. cpp, gopt, ld, crt0.o and libc.a are the shipped ones.
- `make -C host oldroot` builds all of them and installs them into a tree of symbolic links to the WEGA tree
  (`host/tools/oldroot.sh`, default `tmp/oldroot`, bin and lib real directories, guest /tmp shared). Then
  `z8k-emu -r <oldroot> /bin/ccv0p -c -O foo.c`.
- The switches of codgen are set in `codgen/oldcc.h`, the version Makefile names only `OLD_V0` or `OLD_V0P`: the native
  cc takes about 160 characters of -D options.

## 2 Compiler versions

### Dating

Most programs carry the stamp of their start-up file, `@[$]crt0.s Rev : 3.x <date>`, made at the build
(`src/lib/libc/nonseg/crt/mkcrt0.sh`, `crt0.list`); the libc members linked into a program date it too. The passes cparse,
codgen, popt and cas have no stamp; their newest source dates are cparse 10/06/83, codgen 08/24/83, popt 03/25/83,
cas 07/83. The date of a source does not date the compiler that built it.

`OLDCC_DATES.md` (generated by `host/recon/datemap.py`) lists the 373 programs of the tree: crt0 stamp, own SCCS ids,
libc marks, D12 and D1. Two marks can be read from a binary without its source. D12: the old cparse packs the string
literals, the shipped one pads every odd one to an even address. D1, read from the frames of the functions that save
register variables: "slots" (as many never used frame words as saved registers: v1), "tight" (no unused word: v0),
"loose" (shipped).

### shipped

Builds byte-identically: cc, scc, tar, dump, dumpdir, restor, sync, getud, putud, format, verify, copydisk, pburn,
the doscopy programs, the standalone programs, `/usr/lib/libcurses.a` and `slibcurses.a` (1988, without -O) (`make -C host checkall`). All of them are linked with libc members of
09/12/83 or later.

### v1 (01/83 .. 07/83)

- Switches: `OLD_D1`, `OLD_D12` and `OLD_D8L` (cparse), `OLD_D25` (scparse), `OLD_D3`, `OLD_D61`, `OLD_D62` and `OLD_D63` (codgen, scodgen), `OLD_D53` (codgen), `OLD_D24`
  (scodgen), `OLD_D2CW` (scodgen), `OLD_D20` and `OLD_D52` (popt).
- `OLD_D24` and `OLD_D25` (a long cast to a pointer is masked through a copy) are in the segmented v1 since slibPW (07/83):
  xalloc (`(char *)((long)np + usize)`, `(char *)Lastbrk`), regcmp (`sp = (char *)*adx++` through a `long *`), regex.
- `OLD_D2CW` (scodgen, allo3.c allocreg, segmented v1): the copy of a word of a register variable pair (`(int)x` of a
  pointer in rr12: `ld r2,r13`) holds no name, so the next value takes r2 again (slibPW move: `ldb rl2,@rr12`). The
  narrow form of v0's `OLD_D2C` copy rule: for every register copy it costs slibPW regex, xalloc, xlink, xwrite (copies of
  parameters, of an int register variable). One witness (move), limits from the measurements.
- Byte-identical: `/bin/size`, `/usr/bin/strip`, `/bin/mv` (also cp, ln), `/bin/rm`, `/lib/libm.a`, `/lib/slibm.a` (Library.SC 01/83),
  `/usr/lib/libPW.a`, `/usr/lib/slibPW.a` (Library.SC 07/22/83), `/usr/lib/libscreen.a`, `slibscreen.a` (01/30/83),
  `/usr/lib/libu8000.a`, `slibu8000.a` (01/29/83, without -O).
- ld: 55 of 59 functions strictly exact, data equal, corpus 146 of 146; open: place_sec, chk_ranlib, load2td, load1.
- Own code equal, the libc part not linked yet: write (all 5 functions). rmdir: its main differs by D4 and D18.
- Test bench (System III sources of 26 programs from 01/83 .. 07/83): 89 of 121 functions equal, the shipped cc 27.
- stdio of the time (`src/head/oldv7/stdio.h`): `char *_ptr` and the V7 forms of getc/putc (`--_cnt >= 0` first); the stdio.h of the WEGA tree has
  `unsigned char *_ptr` and the other order.

### v1c (02/83, libcisam)

- v1 with a code generator of its own: the v1 switches plus `OLD_D3W` (at the end of a whole condition of `&&`, `||`, `!`
  and behind a `?:` condition the idle word registers go back, pairs stay), `OLD_D2PW` (a register copy wanted in a busy
  register goes to the other half of its pair), `OLD_D3Q` (behind the condition of a `?:` whose arm increments a pointer
  the busy pairs are free: the old scodgen stores through the overwritten address pair), `OLD_D3H` (a register given out
  inside a condition that holds the frame home of a parameter goes back at its end), `OLD_D2CT` (a copy takes over a
  register given out in the last condition; segmented the address pair is taken as it is). Drivers `ccv1c`, `sccv1c`:
  `/lib/v1/cparse`, `/lib/v1c/codgen`, `/lib/v1/popt` (segmented the s-passes).
- Byte-identical: `/usr/lib/libcisam.a`, `slibcisam.a` (Library.SC 02/11/83), the only witness of all five switches;
  `OLD_D3W` and the others under v1 change cp, ln, mv, rm, ld, strip, libl, libPW. Witnesses, counter-witnesses and what
  was tried: `compare/libcisam/COMPILER.md`.

### v1q (before v1)

- v1 with `OLD_D14Q` (codgen); cparse and popt are those of v1. Driver `ccv1q`, runs `/lib/v1/cparse`, `/lib/v1q/codgen`, `/lib/v1/popt`.
- Byte-identical modules of libc-v3.a (the libc in size) from C: filbuf 0_1, rdwr 0_1, malloc 0_1, printf 0_1.

### The time line v1r, v1q, v1

One switch apart each. v1r: no temporary for a return, `?:` through a temporary. v1q: with that return temporary. v1: `?:` without a temporary (changed after 01/05/83, by 01/24/83). The place of v1q between them is a guess: only libc modules witness it, of unknown build time. Not checked: whether v1r needs the cparse of v1 (`OLD_D1`).

### v1r (01/83)

- v1q with `OLD_D1R` (no temporary for the value of a return) and `OLD_D67`. Driver `ccv1r`, its own codgen, its own popt (`/lib/v1r/popt`: without the switches of
  v1, `OLD_D20` and `OLD_D52` came with v1). Byte-identical: `/bin/write`, `/bin/rmdir`, with `libc-isstore.a`; `/bin/od` (`hd`), `/bin/dd`.

### v0 (1982)

- Programs: those of 1982 (sources 07/82 .., crt0 3.1 up to 11/82). Marks: tight frames (no unused frame word, no return
  temporary, leaf functions without a frame) and packed strings.
- Switches: `OLD_D12`, `OLD_D4R`, `OLD_D6T`, `OLD_D6C`, `OLD_D6D`, `OLD_D22`, `OLD_D19P`, `OLD_D19K`, `OLD_D8L` (cparse); `OLD_D2R`, `OLD_D18`, `OLD_D1R`, `OLD_D2W`, `OLD_D10`,
  `OLD_D3P`, `OLD_D4O`, `OLD_D2C`, `OLD_D2F`, `OLD_D2L`, `OLD_D2LP`, `OLD_D2N`, `OLD_D6T`, `OLD_D2T`, `OLD_D6R`, `OLD_D3K`, `OLD_D2V`, `OLD_D2M`, `OLD_D2MO`,
  `OLD_D2P`, `OLD_D2U`, `OLD_D2G`, `OLD_D5S`, `OLD_D5T`, `OLD_D22`, `OLD_D5A`, `OLD_D2W6`, `OLD_D2Q`, `OLD_D2QI`, `OLD_D3K2`, `OLD_D3J` (codgen); none in popt. Not `OLD_D1`,
  not `OLD_D3`. cas: the old one (D17).
- Byte-identical modules of libc-v1.a from C: getpwuid 0_2, getpwent 0_2, fdopen 0_2, isatty 0_1, stty 0_1, ftell 0_1, readsym 0_1, system 0_1, swap 0_2, printf 0_3, fseek 0_2.
- Test bench (System III sources of 38 programs of 1982, `oldcc.sh bench`): 139 of 153 functions equal, 188 differing lines.
- Byte-identical: `/bin/dc`, `/usr/bin/ranlib`, `/bin/sum`, `/bin/mkdir` (the address form of `OLD_D5S`), `/bin/bc` (yacc output of bc.y), `/bin/chkout` (07/23/82; its witness of `OLD_D2LP` and `OLD_D19K`).
- Open forms of the bench: the first register of a statement r2 where ours takes r3 (the getc macro on a global stream);
  the switch dispatch `ld r2,TAB(r3)` against `add r4,r4; neg r4; ld r2,TAB(r4)`; leaf functions without a frame (the
  renaming of register variables into low registers is done by popt `procopt`, in the shipped compiler too).

### v0a (10/82, ex)

- v0 with `OLD_D3AW`, `OLD_D3AC`, `OLD_D2NS`, `OLD_D65`, `OLD_D66` and `OLD_D18A` (codgen); cparse and popt those of v0 (`ccv0a`, `/lib/v0a/codgen`). The own code of ex (crt0 3.1
  10/28/82) follows it, the libraries linked into ex (libc-v1.a, libtermlib-v1.a) follow v0: isatty, stty, gtty in /bin/ex
  are exact with v0 and differ with `OLD_D3AW`.
- Measured 2026-11-23 (`OLDCC_PARAMREGS.md`): ex 323 -> 339 of 391 functions exact, none lost; 340 with `OLD_D3AC`. The programs of 07/82
  contradict the switch: with it chkout loses apply, getat, nextcmd, notplain, doit (15 -> 10 of 18 exact), dc 13
  functions, ranlib 2, the v0 modules of libc-v1.a 10. mkstr (11/82) has no place the switch touches.
- Date line (measured 2026-11-23, own code compiled by ccv0 and ccv0a, functions against the originals): with v0 and
  against the switch: cron (07/23/82), join, ptx (07/24/82), banner, sdiff (07/28/82), besides chkout, dc, ranlib; with
  v0a: ex (crt0 3.1 10/28/82), xstr (11/01/82: hashit, found exact only with it; xgetc reloads its parameter for
  `_filbuf` as v0a does). echo (08/12/82), cat (10/29/82), mkstr, at, expand (11/01/82) have no place it touches. So
  the switch came between 07/28/82 and 10/28/82; no program of the tree in between has such a place. (guess) It came
  with the build that stamps crt0 (3.1): every v0 witness has no crt0 stamp, every v0a witness has one.

### v0p (the compiler of the passes)

- v0 with the differences that only the passes show. It built cparse, scparse, codgen, scodgen, popt, spopt and cpp: all
  seven are byte-identical, all their functions strictly exact.
- Switches: those of v0 (without `OLD_D2QI`, `OLD_D3K2`) and `OLD_D3KC`, `OLD_D3J`, `OLD_D2PO`, `OLD_D2X`, `OLD_D3AW`, `OLD_D12K`, `OLD_D5G`, `OLD_D2A`, `OLD_D2O`, `OLD_D2QO`, `OLD_D2MO`,
  `OLD_D2PT`, `OLD_D16A`, `OLD_D6S`, `OLD_D3L`, `OLD_D23` (codgen). popt needs no switch.
- The corpus of cparse and scparse holds only with the ccv0p build: the heap contents of the .S file follow the data layout of the pass.

### vk: the compiler of the kernel objects

The objects of `/wega` (`usr/sys/sys/LIB1`, `usr/sys/dev/LIB2`) were made by an older scc. `sccvk` (`-DSCC -DOLD_VK` in `src/cmd/cc`) runs `/lib/vk/scparse`
(built in `src/cmd/cc/cparse/build/segvk`, `OLD_D25`), `/lib/vk/scodgen` (`src/cmd/cc/codgen/build/segvk`, `OLD_VK` in `oldcc.h` = `OLD_D3` and `OLD_D24`) and the
`/lib/vk/spopt` (`src/cmd/cc/popt/build/segvk`: the shipped spopt with `OLD_D29`). No source form gives them; sccv1 (v1 scparse and spopt) is further away. Witnesses (identical):
ureg, sys1, tt0 (D3), sig, sys2, sys3, debug (D24, D25), lock (D3), tty (D29). The `make install` of `src/uts` is identical in all 31 files, `wega` and `LIB2` included.

- Switches: `OLD_D3`, `OLD_D24` (codgen), `OLD_D25` (cparse), `OLD_D29` (popt); section 3.

### vl: the compiler of libc.a and slibc.a

The C members of `/lib/libc.a` and `/lib/slibc.a` (sources 08/83 and 09/83) come out of the shipped cc and scc except a few;
their compiler was the shipped one a little earlier. `ccvl` and `sccvl` (`-DOLD_VL` in `src/cmd/cc`, built in
`build/nonsegvl`, `build/segvl`) run the shipped cparse, gopt and popt (spopt), `/lib/vl/scparse` (the shipped one with `OLD_D25`) and `/lib/vl/codgen`,
`/lib/vl/scodgen` (`src/cmd/cc/codgen/build/nonsegvl`, `build/segvl`; `OLD_VL` in `oldcc.h` = `OLD_D53`, `OLD_D57` and `OLD_D24`).
All 206 C members of the two libraries come out exact; the source forms they need are in the sources (doprnt: `_pfile != NULL &&
ferror(_pfile)` and the block `lng:` behind the cases `O X U D l`; segmon: `char *mkseg()`, `sr[0].sr_seg`, `(i = i + 1) <=
*nsegs`; slibc malloc: `union store *r` in front of `register unsigned onw` in realloc and an unused `int spare` in calloc).
Both libraries are built by vl
(`CC = ccvl`, `SCC = sccvl` in `src/lib/libc/Makefile`; owner's decision), so
checkall measures every rule of vl on all their members. vl itself is compiled by the shipped cc: in stage 1 linked with
the shipped /lib/libc.a (and the old printf), in stage 2 with `libc-v5.a` (codgen) and `libc-v8.a` (driver). No member of the two libraries is left in `oldcc/`.

### vm: the cparse of the programs of 11/18/83

The programs with the SCCS lines of 11/16/83 .. 11/18/83 (`87wega3.2`) give some register locals an unused frame word
(D1, register slots). `ccvm` (`-DOLD_VM` in `src/cmd/cc`, `build/nonsegvm`) runs the shipped passes with `/lib/vm/cparse`:
the shipped cparse with `OLD_D1S` (`lookup` in sym1.c does not clear `sfldc` of a new symbol entry; the entry is
malloc'd and can be a freed one whose `sfldc` still holds the 1 of a register parameter, and `oalloc` then gives the
register local a frame word). Built by cc with the libc of stage 1 as the other old passes (the malloc decides which entries are stale: those of
`libc-v7.a`, linked into the shipped cparse, and of `/lib/libc.a` give the same words, measured on the test set). Which local gets a word depends on every symbol entry made before it in the file (`OLDCC_REGSLOTS.md`).
Built by vm and byte-identical: ar, cmp, cpio, diff, du, getfile, grep, mail (rmail), make, nl, pr, putfile, remote, who. Source forms it needs: make's defs includes the headers of files.c (pwd.h, ar.h, s.out.h, nlist.h);
make files.c eqstr keeps an `int unused`, mail an unused `<sys/dir.h>` (the entries in front of the first function that
are not in the bytes). The undated tar, dump, dumpdir, restor and the standalone programs get words from it that they lack:
they are of the shipped cparse.

Rebuilding a program of vm: no spare locals for these words. Which register locals get one depends on the number of
permanent symbol entries made before them in the file: every global name, typedef, struct tag and member of the
headers and of the file itself, also declarations that make no code, and the functions called before (an implicit
declaration is an entry too). When the frames do not match: first the sccsid (`static char sccsid[]`, one entry) and
the includes of the WEGA source (make: the headers of files.c in defs, 63 entries); then measure how many entries more or
fewer in front of the first function (or of a later one) give all functions right: `host/recon/regslots/extradecl.py`
(on the test set of `setup.sh`: the program in its list and its words in `hyp.py`), or real builds with N dummy `extern int`
declarations; then find a plain form with that many entries (a header, declarations of the libc functions it calls).
Which entries the original had is not in the bytes; a form that fits is recorded in `findings.json` as an odd form
(mail: an unused `<sys/dir.h>`). A word that no count gives stays an unused local (make eqstr).

### The old scc of cas

cas was built by an older scc; its parser and `assemble` without `-O`, the other modules with `-O`. The working compiler
`sccvc` is v0p compiled for segmented code (every switch of v0 and v0p that vc does not have is neutral on cas, alone and
all together), with these differences:

- codgen (`OLD_VC` in `oldcc.h` defines `OLD_V0P`): without `OLD_D3KC` (cas copyfile: a parameter wanted in its register is
  taken as it is, as in v0), with `OLD_D13` (bit 31 of addresses), `OLD_D6J` (the dense jump table, segmented), `OLD_D24`
  (the mask of a long cast to a pointer, as vk), `OLD_D2S` (symtype), and for gopt (neutral on cas)
  `OLD_D2FA`, `OLD_D2XP`, `OLD_D2TC` (section 3, D2..D4),
  `OLD_D14T` (section 3, D4) and `OLD_DNR`: the register records of gopt (F R S T, only with -O3 and -O5, which no build of
  the tree uses) are not read, their code (fcmd, rcmd, scmd, tcmd, memname, findtemp) is left out for room. The text of the
  vc scodgen is near the 64 KiB of a nonsegmented program; /bin/ld does not report an overflow (sg_code wraps, the program
  runs into zeros), the codgen Makefile stops then. Measured as the tree links it: `LIBC="../../../../lib/oldlibc/printf/s1p.o
  ../../../../lib/oldlibc/doprnt/s1d.o ../../../../lib/oldlibc/doprnt/s1f.o /lib/libc.a"` (the three objects from a checkall
  tree), then `od -An -tx1 -j28 -N2 build/segvc/scodgen`. Room is freed inside the OLD_* blocks without changing behaviour
  (helpers, merged tests, `goto blk`); a segmented port of the codgen does not work (the NODE union of mfile3 assumes 16-bit
  pointers);
- scparse (the segvc rule): the switches of v0p (`OLD_D12 OLD_D4R OLD_D6T OLD_D6C OLD_D22 OLD_D6D`) with `OLD_D13`,
  `OLD_D25` and `OLD_D12R` (gopt, neutral on cas: the static area of a function that returns a structure is zeros in the data,
  written at the start of the next function (or at the end of the file), behind the function and its switch tables, not in
  the bss: /lib/gopt constfold, 7:5904). `OLD_D12` gives the data layout of /bin/cas in the real build (strings at the end of a file's data, unpadded);
- spopt: the shipped one with `OLD_D13`, `OLD_D45`, `OLD_D20S`, `OLD_D49`, `OLD_D50`, `OLD_D51` and `OLD_D64` (gopt, neutral on
  cas: memreg of z22.c takes the offset of `|_stkseg+~L1+4|(fp)` behind `~L1`; the shipped one reads `+~L1` as 0, so every
  store to a frame slot clears every register known to hold a frame slot; /lib/gopt domspace keeps b in r3) (v0p has no switch in popt).

Which switch has which witness in cas and gopt: `OLDCC_SWITCHES_VC.md` (all blocks of v0p are measured there on both
programs; a switch without a witness is in vc because it is in v0p). `sccvc` is the compiler of `src/cmd/cas/Makefile` (`old/cas` stays with scc;
sccvc passes `-DSCCVC` to cpp, for the one form of cas the shipped scc cannot compile: `TABADDR` in cas.h):
`src/cmd/cc/build/segvc`, `/lib/vc/scparse`, `/lib/vc/scodgen`, `/lib/vc/spopt`, `/lib/old/cas`; linked with
`src/lib/slibc-v11.a`. The real build (`make` in `src/cmd/cas`, stripped) is byte-identical with `/bin/cas`; the state
per function is in `compare/cas/FINDINGS.md`. The libc part of /bin/cas was not made by the tools of its own modules: its
address constants have bit 31 clear (the shipped assembler; the cut members `NAME/0_2.s` of `src/lib/oldslibc` are assembled
by `cas`, not by the assembler of sccvc), `errlst` has the data order of the old compiler (both tables, then the strings:
`../libc/common/gen/errlst.c` by sccvc), and in `printf` the common `_rc` stands in front of the reference to `__pfile` (the
linker places commons in the order of the symbols, `_rc` in front of `__pfile` of doprnt).

A switch on a constant (`switch (sizeof(char *)) { case 4: ...; case 2: ...; }`): sccvc, ccv0 and the shipped cc load the
value into r2 and keep only the matching case, without a dispatch (`ldk r2,#4; calr igetl`); the shipped scc keeps the jump
and both compares. Witnesses in /bin/cas: igetaddr, putrow (the only two `ldk r2,#4` without a use).

### The old libc members inside size, strip, ranlib, cas

The Jan 1983 libc linked into these binaries shows D14 and differs from the shipped members by its source and by the
compiler (D1, D8). Its members are kept as cas sources in `src/lib/oldlibc`.

## 3 The differences

Each class: the form in the code, the pass, the mechanism, the switch, the witnesses. D21 is not used.

### D1 Frame size and frame places

- v1 (`OLD_D1`, cparse, `oalloc`): every register variable gets a place in the frame too, at its declaration, like an
  automatic variable of its type; the shipped one only char and short register variables under -O. ld, strip `copy`, mv.
- v0 (`OLD_D1R`, codgen, `delay`): no temporary for the value of a return; with a delayed x++ the value stays in r2, which
  stays taken while the increment runs (`ld r2,_crslab; inc _crslab,#1`: cparse getlab).
- v0: no frame for leaf functions, no home slots for register parameters.
- v1 (`OLD_D1`): the frame place of a register variable lies where it is declared; a free word in front of a variable of the
  original can be that place (time main: `register p` in front of the longs, date main: `register char *tzn` in front of
  `tb`; both byte-identical by the order of the declarations, 2026-11-24).
- Not reproduced: one unexplained frame word in main, endload, slookup, pslookup, index16 of ld (kept as `int spare`);
  cas `putins` 12 bytes against 14, libc nlist and length 2 bytes smaller, fseek 14 against 20.
- vm (`OLD_D1S`, cparse, `lookup`): register slots of 11/83: a register local gets an unused frame word when its

### D6 switch

Up to 3 cases compared one after the other, the dispatch in front of the bodies; with 4 or more a `cpir` table, values sorted,
bodies in source order. The shipped compiler uses `cpir` from 1 or 3 cases on, values, then a jump table behind the bodies.

- v0 `OLD_D6C` (cparse genswitch): up to 3 cases compared, the table from 4 cases on.
- v0 `OLD_D6T` (cparse genswitch, codgen gswitch): the value list stands right in front of its target list, and the target is
  loaded from the pointer cpir leaves behind (`ld r2,%0024(r3)`). Our cparse passes the values to codgen in a record `V swlab dlab
  tlab values` in front of the `C` record; this intermediate form is a guess.
  Segmented (vc, cas: escape, osymout, genwop, yyparse): the same lists; the target from the offset cpir leaves behind, less that of the
  second value, rotated, as the index of the targets, into the pair of the value: `ld r2,#Lv+2; sub r7,r2; rl r7,#1; ldl rr2,Lt(r7);
  jp @rr2`; the count of cpir neither in that pair nor in rr0 (r4).
- vc `OLD_D6J` (codgen gswitch, segmented): a dense jump table loads the target into the pair of the value (`rl r2,#2; ldl rr2,Lt(r2);
  jp @rr2`), as the nonsegmented one into the value register; the shipped one takes another free pair (rr6). Not for a value in
  rr0. cas: iputexpr, main, defsym, p2tag, asmins, getop, error and others.
- v0, v0p `OLD_D6D` (cparse genswitch): the limit of the jump table is 3 values per case, `range <= 3*(n-1)` where `n` counts one more than the cases; the shipped one `range <= 3*n` (zzzcode, switch of

### D13 Pointer constants (old scc)

### D14 Varargs prologue and post-increment (old libc members)

`OLD_D14Q` (v1q; codgen store, the QUEST of order, freeparm, delay): the value of a `?:` of an integer type always goes through a temporary of the parameter area, at the start of the frame (`@r15`, the

### D16 Frame operand in arithmetic

v0p `OLD_D16A` (codgen, match): `++n` of a frame slot whose value may go to a temporary (cookie with INTEMP: the left operand of `*`)

### D17 Jump and call form: the old cas

`callr` and `jpr` are decided by cas. The old cas runs its jump optimization (`optim`) also during the first pass, and a forward jump
to a label not defined yet becomes long there. Built with `-DOLD_CAS` (`host/cas/casold`, `src/cmd/cas/old`, `/lib/old/cas`).

- At an opening `{` with 176 undecided entries or more (`OLD_ENTBLK`; dc: the `{` of getwd has exactly 176, so its call of putwd stays long). The label of the
  function in front of the `{` is known then.
- When an entry would be made behind 255 entries (`OLD_ENTMAX`): functions too long for the first rule, yylex, rmove.
- A forward jump does not count a jpr that stands at its label (`>`, the shipped cas has `>=`): acon. One witness.

Why these limits is not known. Also dc of 07/82 follows the rule: from the System III source, split in front of add0 as WEGA has dc1.c
and dc2.c, all forms right. The manual (ZEUS Languages Programming Tools 3.2 and Band B, 3.4.5) names two
more conditions, `.=` and a difference of labels with a jump between them; no input has a case that depends on them, so they are not
built. The shipped cas and the ZEUS cas do not have them.

ex (10/82, v0a) follows the rule too: with the old cas all 394 functions of /bin/ex are exact (with the shipped cas 24 differ by call/calr and jp/jr only).

A `call` also comes from a callee in another module, because `calr` cannot leave a module. So sputc and aobeg of cparse are a module of
their own (sym2.c, the name is a guess), and hash, upoff, oalloc belong to sym1.c.

### D19 Order of evaluation of the operands of a binary operator

### D20 Code motion of popt

- v0p: no old popt. The models built with the original /lib/popt as the pass of ccv0p are byte-identical to those with our popt.

### D22 Doubles in rq4

### D65 The difference of two address constants

### D66 The base register of a structure copy

### D23 Zero addend

### D24, D25 Mask of a segmented address

The kernel masks a user address with `(caddr_t)((long)x & 0x7F00FFFF)`. Original: `ldl rr4,rr2; and r4,#%7F00; ldl y,rr4` (a copy in a new pair, the mask on the copy); the shipped scparse and scodgen: `and r2,#%7F00; ldl y,rr2`.

- vk `OLD_D25` (cparse local1.c, SEG, PCONV): a cast of a long to a pointer stays a conversion (SCONV); the shipped scparse paints the type.
- vk `OLD_D24` (codgen, reader3.c optpre and optpost around optim): `rmconv` keeps a conversion between a pointer and a non-pointer of the same size. The SCONV of a long to a pointer then uses the template 040a (`ldl VA1,ALX; and A1,#%7f00`: the copy and the mask), and an `& 0x7f00ffff` under it is dropped. The address of a frame place (a local struct, the argument area at 0(fp)) is loaded by `lda` without that mask (local3.c ZL): vc /lib/gopt has 31 such lda (struct copies to a local, struct arguments), none with the mask; neutral on cas, the kernel (vk) and the libraries (v1, vl).

The two work only together: each alone gives the code of the shipped compiler. Witnesses: `sig`, `sys2`, `sys3`, `debug` of the kernel. vc has both too (`OLD_D24` in `OLD_VC`, `OLD_D25` in the segvc rule of scparse): cas `yylex` (`(struct pst *)(q->s_2 & 0x7F00FFFFL)`: `ldl rr2,rr0; and r2,#%7F00`) and `igetaddr` (`return ((struct irow *)igetl());`: `ldl rr0,rr2; and r0,#%7F00; ldl rr2,rr0`). In cas a node holds its operands in pointer members of its union and a symbol its name in `s_name` (a union with the value `s_2`), so that only these two casts of a long to a pointer are left; with a cast at every node operand D25 would mask them all. vl has both too (`OLD_D24` in `OLD_VL`, `OLD_D25` in the segvl rule of scparse, `/lib/vl/scparse`): slibc malloc (`setbusy`, `clearbusy` with `INT` = `long`: `(union store *)((long)(p)|BUSY)`; the first call sets `allocs[0].ptr = setbusy(&allocs[1])`: `ldl rr4,rr2; and r4,#%7f00`); D24 alone changes nothing there, nonsegmented D24 changes no libc member. No source form replaces them: 25 forms of the statement in `sig` (casts, `L` constants, order of the operands, `~`, `+ 0`, `| 0`, a long lvalue, parentheses) give the same code, temporaries are worse.

### D29 Layout of a table switch

vk `OLD_D29` (popt z21.c, `d29switch`, on the raw nodes of a function before the first pass of `iterate`). The raw code

    Lh: ld r,x; jp Ld; bodies; jp Lb; Ldf: default; jp Lb; Ld: cp r,#n; cjp ugt,Ldf; rl r,#2; ldl rr,t(r); jp @rr; Lb: jp Lo; Lk: block; jp Y

(a table switch with its default in front of the dispatch, left by a jump to the next statement) is laid out as

    Lt: rl r,#2; ldl rr,t(r); jp @rr; bodies; Lb: code at Lo; Lk: block; jp Y; Lh: ld r,x; cp r,#n; cjp ule,Lt; Ldf: default; jp Lb

Only the layout changes, what runs is the same. From this the shipped optimizer makes `TCXONC` in `ttiocom` of `tty.o`: the dispatch in two parts (`rl; ldl; jp @rr` in front of the bodies, `ld; cp; jr ule; jp default` behind `TCSBRK`) and the common tail behind the last body. The tail comes from `xjump`, which needs the label the bodies jump to right behind the last body and no `jp` right behind that label. One witness (`tty`, the source is the plain `switch` of System III); the evidence rule of two functions is not met. The raw code of the old compiler is not known, this is the layout that gives the bytes (owner decision). `/lib/vk/spopt` is the shipped spopt with this switch; the other objects of vk stay identical.

### D45 A conditional jump over a jump, and codemove

### D50 The loop inversion goes on at the target of a jump

### D52 A conditional expression in front of the function exit

which v1 does not build). Another limit: A is more than one instruction (regex of libPW, `return(!af)`: A `ldk r2,#1` and Y `ldk r2,#0` stay;
strncmp of the shipped libc, A `sub r2,r2`, falls out too). One witness (one source, two objects).


### D53 No temporary for a return value in a function with a large frame

vl and v1 `OLD_D53` (codgen reader3.c, `delay`; v1 since 2026-11-24: nlist 0_1 of libc-v9 in /bin/df, 04/83, the same picture). The shipped codgen takes a temporary of the frame for the value of every
`return (e)` (it holds the value while a delayed `x++` runs). The codgen of vl takes none in a function whose automatic
variables fill more than 10000 bits (1250 bytes). Witness: nlist of libc.a and slibc.a (`nlist()`: 1592 and 1602 bytes of
automatic variables, the frame 2 bytes smaller than the shipped one's; `readby` in the same file has the temporary). The
bound is only known to lie above 1170 bytes (execvp of slibc keeps the temporary) and at or below 1592; why the old
compiler does so is not known (`OLDCC_LOG.md`). One source, two objects.

### D57 The entry store of a register parameter used as memory

vl `OLD_D57` (codgen lcl3.c clocal, local3.c efcode, reader3.c). When a function takes the address of a register parameter,
the store of that parameter in the entry code is written with its offset also at offset 0 (`ld 0(r15),r7`); the shipped
codgen writes `@r15` there as for every other parameter (a narrower form of `OLD_D18` of v0, which writes every offset 0
so). Visible only nonsegmented (the segmented store always names `|_stkseg+...|`). Witness: swap of libc.a (`swap(x)`
takes the bytes of `&x`). No form of the body of swap gives it without the switch (the entry code prints `@fp` for the
first parameter whatever the body: `t + maxoff` is 0 there). One witness.

### Register allocation of the old scc

The register variables are assigned in declaration order from r13 downwards; an int or char takes one register, a pointer or long the highest
free aligned pair; a `register` parameter comes first. A leaf function puts them into scratch registers. (Nonsegmented cc: from r14 downwards.)


### D61 The float need of a binary node

v1 `OLD_D61` (codgen, scodgen; order3.c sucomp). The last case of sucomp takes the float need `fsu` of a binary node by
`fr == fl` (the float needs of its operands); the shipped codgen asks `sur == sul` (the word needs) there. In a left-deep
float expression whose right operands are in memory (`(p4*x+p3)*x+p2 ...`) the shipped need stays 2, the v1 need grows by 1
per level: at 5 (above `ffregs`, 4) store() writes the subtree of need 4 to a temporary and loads it again (`fldd t,f3;
fldd f3,t`), every third operation, and the right operand of a division goes to a temporary first. Witnesses: the members
of libm.a and slibm.a (atan xatan, exp, gamma, j0, j1, log, sin, sinh, tan; System III sources). `if (0)` (never the
special case) gives the same bytes on libm; `fr == fl` is the plainer form.

### D62 A float compare with memory without rounding

v1 `OLD_D62` (table3.nzcc.c rule 052, table3.szcc.c rule 047a). A float register compared with a memory operand: the
shipped rule rounds the register first (`fld dbl, f2,f2` before `fcpd f2,mem`), v1 compares it as it is. Witnesses: every
float compare with memory of libm.a and slibm.a (asin, fmod, hypot, tanh, pow, jn and the rest).

Neither switch changes a program of v1 that was byte-identical before (checkall).
### D63 A float widened to double stays a conversion

v1 `OLD_D63` (codgen, scodgen; reader3.c optpre: hidden from rmconv). The shipped codgen drops a conversion float to double over an operand
(`SCONV` double of a float), so `f1 < f2` of two floats compares `flds f0,f1; fcpxs f0,f2` (rule 052, register against
memory). The v1 codgen keeps the conversion: both operands have the float need 1, each is loaded into a register
(`flds f0,f1; flds f1,f2`) and rule 051 compares the registers (`fcpx f0,f1`). A double operand has no conversion and still
goes against memory. Witness: itcompare of libcisam.a (FLOATTYPE, `if (f1 < f2) ... else if (f1 > f2)`). One witness.
Changes no program of v1 that was byte-identical before (checkall).
